Defect found and fixed during this step

BUG-002 — Min rating filter silently ignored (found and fixed in this session):

Reproduction: On /products, type a decimal value (e.g. 4.3) into the "Min rating" field, click Apply. Expected: listing narrows to products with avg_rating >= 4.3. Actual (before fix): the listing did not change at all — no network request was even sent (confirmed via Playwright's network-request log and a window.fetch instrumentation probe).

Root cause: the "Min rating" <input type="number" min="0" max="5"> had no step attribute, so the browser defaults to step="1". A decimal value like 4.3 fails the browser's native HTML5 constraint validation (step mismatch), which silently blocks the enclosing form's submit event — no exception is thrown, no error is shown, the click simply does nothing. This is why it survived Step 6's 31 passing component tests: those run in jsdom, which does not enforce native form constraint validation, so the bug was only reachable via a real browser.

Fix: added step="0.1" to the input in frontend/src/features/catalog/ProductListingPage.jsx. Re-verified in a fresh headed browser session (screenshot: uat-bug002-fixed-min-rating-filter.png) — the filter now correctly narrows the listing to only the Wheelchair (rating 4.5), excluding the Cane (rating 4.1). All 31 frontend Vitest tests still pass after the change.

Known, accepted gap (not a defect — documented in the design/spec)

The Gherkin AC for "Product detail view" lists specifications among the visible content. The current implementation always returns specifications: {} (empty) — per docs/design/services/catalog-service/design.md, this field is meant to aggregate product_variant_attributes/product_variant_extra_attributes, which are part of US-011's (not-yet-built) vendor-catalogue write path and are not populated by this story's read-only demo seed data. This is a pre-existing, documented scope boundary (see docs/design/services/catalog-service/data-model.md), not a new defect discovered in this step — flagged here for reviewer awareness, not logged as a bug.
