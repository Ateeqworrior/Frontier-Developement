Bug found and fixed during this step

BUG-001 (fixed in this session): The demo seed data in main.py uses placeholder image URLs (https://example-cdn/...) that don't resolve to a real host. ProductListingPage.jsx and ProductDetailPage.jsx rendered <img> tags with no error handling, so a broken-image icon appeared on every product card/detail page — purely a demo-data artifact, but the missing onError handling was a real, reusable gap (any 404'd/expired image URL — including a real S3 URL — would have shown the same broken icon).

Fix: added an onError handler to both <img> elements that hides the element on load failure (frontend/src/features/catalog/ProductListingPage.jsx, ProductDetailPage.jsx). Re-verified via Playwright: the accessibility snapshot no longer includes the broken img node, and the visual screenshot before/after confirms no broken-icon UI. All 31 frontend Vitest tests still pass after the change.

Note on Jira logging: the jira MCP server was not connected during this step (same unavailability as Steps 5–6), so this bug was not filed as a formal Jira ticket — it was found, fixed, and re-verified within this same session instead, so no bug remains open regardless. The residual browser console error (net::ERR_NAME_NOT_RESOLVED for the placeholder image URLs) is an artifact of the fake example-cdn demo-seed domain, not an application defect — it will not occur with real S3-hosted product images.
